# ADR 0009: Фото ДЗ — напряму в S3 через presigned URL

- **Статус:** Прийнято, 2026-11-13
- **Пов'язане:** [PROJECT.md → «Домашні завдання»](../../PROJECT.md#домашні-завдання), `backend/app/storage.py`

## Контекст

Учень здає ДЗ текстом і фото. Обмеження:

- Function URL і Lambda обмежують розмір запиту (6 МБ), а фото з телефона бувають більшими. До того ж передавати байти через API Lambda — це оплачений час виконання.
- API Lambda не має мережі до S3 (без NAT і endpoints).
- Локально в compose дозволені лише PostgreSQL і backend, без MinIO.

## Рішення

1. **Браузер завантажує файл напряму в приватний S3** за presigned POST. Політика POST обмежує `Content-Type` (JPEG, PNG, HEIC) і розмір (до 10 МБ), посилання діє 15 хвилин. Перегляд — presigned GET на 15 хвилин.
2. **Підпис — локальне обчислення** з креденшелами ролі API Lambda, без звернення до S3. Тож мережа не потрібна, і це перевіряє тест, який забороняє сокети.
3. **Ключі генерує сервер**: `homework/<lesson_id>/<uuid>.<ext>`. При здачі ДЗ приймаються лише ключі цього заняття.
4. **Локально** — `LocalStorage`: файли на томі `uploads`, а API сам приймає завантаження й віддає файли за HMAC-підписаними посиланнями (`/api/files/...`) з тим самим контрактом, що й у S3. У хмарі ці ендпоінти відповідають `404`.

## Альтернативи

- **Завантаження через API** — ліміт 6 МБ і зайвий час Lambda.
- **Gateway endpoint S3** безкоштовний і дав би API Lambda доступ до S3, але для presigned URL він не потрібен.
- **MinIO в compose** — це ще один сервіс, а обмеження проєкту його забороняє.

## Наслідки

- Бекенд не перевіряє, що файл справді завантажено: фото, якого немає, просто не відкриється.
- Завантажені, але не здані файли лишаються в S3. Це відкрите питання в PROJECT.md: прибирати ключі без рядка в `submission_photos`.
