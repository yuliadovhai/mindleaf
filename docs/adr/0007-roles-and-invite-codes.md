# ADR 0007: Три ролі й коди запрошення замість зіставлення за email

- **Статус:** Прийнято, 2026-11-13
- **Пов'язане:** [PROJECT.md → «Ролі»](../../PROJECT.md#ролі), міграції `0002`–`0003`

## Контекст

Спочатку входити міг лише репетитор, а учні й батьки були записами в його картці. Тепер учень і батьки мають власний кабінет. Треба вирішити, як акаунт Cognito дізнається, чию картку йому показувати і з якими правами.

Обмеження:

- **Email недоступний бекенду.** Access token Cognito не містить email, а API Lambda без інтернету не може викликати `/oauth2/userInfo`. Зіставлення «email у картці = email акаунта» потребувало б pre-token-generation trigger (ще одна Lambda) або передачі ID token.
- **Кілька дітей і кілька батьків.** Один батько може мати кількох дітей, зокрема в різних репетиторів. У картки може бути кілька батьків.
- **Ролі різні за правами.** Учень не бачить грошей; батьки бачать гроші, скасовують заняття, але не здають ДЗ і тести за дитину.

## Рішення

1. Таблиця `tutors` стає `users` з колонкою `role` (`tutor` | `student` | `parent`, `null` до вибору). **Одна роль на акаунт, назавжди.**
2. Репетитор обирає роль сам (`POST /api/me/role`). Учень і батьки отримують її з **першого використаного коду запрошення**.
3. Код генерує репетитор у картці учня окремо для учня чи батьків. Він одноразовий, діє 7 днів, 8 символів без схожих літер. Зберігається лише SHA-256 коду.
4. Доступ — це рядок `student_links (user, student, relation)`. У картки щонайбільше один акаунт учня (частковий унікальний індекс), батьків — скільки завгодно. Репетитор бачить прив'язки й може їх прибрати.
5. Перевірка ролі — FastAPI-залежності `get_current_tutor` / `get_current_member` (`403`). Перевірка доступу до картки — у сервісах (`404`, як для неіснуючого запису).

## Альтернативи

- **За email.** Відкинуто через обмеження вище і через ризик помилок: опечатка в email відкрила б чужу картку.
- **Кілька ролей на акаунт із перемикачем.** Гнучкіше (репетитор, який водночас батько), але кожен ендпоінт мусив би знати «від імені кого» діє запит. Для першої версії складність не виправдана: репетитор-батько може мати другий акаунт.
- **Багаторазовий код на картку.** Простіше видавати, але витік коду відкриває картку будь-кому. Одноразовий код і список прив'язок дають репетитору контроль.

## Наслідки

- Новий акаунт без ролі отримує `403` на всьому, крім `/api/me` і `redeem`: фронтенду потрібен екран вибору.
- Наявні репетитори стали `tutor` міграцією `0002`; їхні дані не змінились.
- Перебір кодів не обмежено rate limit. 31⁸ ≈ 8.5·10¹¹ комбінацій і термін 7 днів роблять його непрактичним, але при підозрі варто додати ліміт спроб.
